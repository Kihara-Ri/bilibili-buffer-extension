# 个人 B 站内容服务：目标、约束与路线

适用版本：内容服务 0.1.0；最后核对：2026-10-27（Asia/Tokyo）。这是内容服务的产品范围依据；当前 API 以 [API.md](API.md) 和实现为准，前端交接见 [HANDOFF.md](HANDOFF.md)。

## 目标与成功标准

让用户在 iPhone 浏览器使用自己的轻量、纯净入口，管理 B 站内容，按实际价值选择看原视频或读文字，不必日常打开官方网页或 App。账号登录和采集在自托管服务器完成，用户掌握来源、筛选规则和通知强度。

长期需要历史、稍后再看、收藏夹、关注与 UP 更新。对于重视画面、声音、表演或叙事体验的作品保留完整观看；资讯或口述可以提供带依据的文字；操作演示可结合关键片段。用户的选择优先于 AI 建议。扫码授权仍需 B 站完成，不能把“纯净入口”理解成永不与平台交互。

成功不按播放时长、点击率、日活、刷满推荐条数衡量，而看能否可靠取得用户授权的内容、减少无用操作、保留作品体验，并能解释和纠正 AI 判断。没有合适内容时可以不推荐、不通知。无推广界面是产品目标；当前不具备识别或删除视频内商单的能力。

## 用户已确定的约束

- Codex 当前只实现基础后端与接口；UI、二维码展示、播放器控件、iPhone 布局由 Claude Code 负责，不能把前端设计当成已确认需求。
- 核心获取引擎归入 bilibili-buffer 的 `server/content/`，作为独立 Python 服务；不在 MV3 内运行 Python，不把服务和账号数据打进扩展 ZIP。
- 部署目标为 rasp5remote，公开地址为 `https://bilibili.kihara.cn`；B 站登录态在服务端保存，手机不各自登录 B 站。
- 只读接入：不主动点赞、评论、关注、收藏、删除稍后再看或上报观看进度。将来如需站内写回，应另立显式用户操作契约。
- Cookie、二维码凭据、媒体签名 URL 不交给模型、不进入公开文档或访问日志。独立站点认证和 B 站登录必须分开。
- 同步失败不伪装成空列表；没有字幕、字幕受限、采集失败和未分析不能混为一谈。
- 字幕只能证明读过接口返回的文字；抽帧只能支持抽样判断，均不等于看完整片。
- 原始内容、AI 处理状态、用户读过摘要、真实播放进度、B 站观看历史分别建模，不能相互推断。

## 当前功能与证据

| 功能 | 实现状态 | 当前验收边界 |
| --- | --- | --- |
| URL/BV、分 P、内容版本 | 已实现 | 公共真实视频及模拟多 P 测试通过；无 av/b23/番剧入口 |
| 扫码登录、保存登录态、本机注销 | 已实现 | 公网 QR 生成和未扫码轮询通过；真人扫码确认和重启后认证复用待验收 |
| 稍后再看分页同步 | 已实现 | 完整替换、失败保留、失效条目单测通过；树莓派后台账号同步待真实登录验证 |
| 字幕、逐段引用、AI 字幕标记 | 已实现 | 原型曾用浏览器读取真实字幕；正式服务登录后的采集待验收，无 ASR |
| 单段 MP4、短期代理、Range/HEAD | 已实现 | 公网匿名 MP4 206/HEAD 通过；实际 quality=16，账号高清与 iPhone 播放待验收 |
| 本地作品/作者屏蔽 | 已实现 | 本地访问规则，不修改 B 站账号 |
| HTTPS、独立站点认证、自动启动 | 已部署 | TLS 可信、未认证 401、外站 Origin 403、Secure Cookie 与 systemd 状态已核对 |
| 历史、收藏夹、关注列表 | 未实现 | 没有对应 API，不用稍后再看冒充 |
| UP 更新、调度、私人推送 | 未实现 | 没有订阅、游标、通知权限或后台投递服务 |
| 自动摘要、看/读路由、探索推荐 | 未并入此服务 | 原型已有离线审阅实验；不代表生产部署包含模型任务 |
| 手机 UI、播放器控件、PWA | 未实现 | Claude Code 接入范围，未做真机验收 |
| DASH/HLS、离线完整下载、缓存互通 | 未实现于内容服务 | 扩展已有能力不等于手机服务已具备 |

原型目录 bilibili-discovery 曾完成账号浏览器采集、字幕和 Agent 审阅，它与正式服务的数据库、登录态、部署分别存在。未将私人数据迁到服务器。两者职责见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 后续顺序与完成条件

以下是基于当前依赖关系的工程顺序，不代表这些新能力已获实现或上线。

1. **完成已有后端验收**：真人 QR 确认、重启后状态、稍后再看完整同步、受限/失效视频、字幕及账号权限失败；不能以匿名公共视频替代。
2. **Claude Code 薄前端**：在同一域名接上登录、队列、解析、字幕与播放器，iPhone 实机验证起播、拖动、分 P、令牌过期恢复；不自动生成观看历史。
3. **补齐账号资料库**：历史、收藏夹、关注分别定义分页/游标与稳定 ID，先实现失败保留与幂等，再接前端。历史只承诺平台实际返回范围。
4. **UP 更新与私人通知**：先增量采集、去重和重试，再选择通知渠道；重点 UP 更新不被 AI 质量门槛隐藏，不通过自动评论 @ 用户通知。
5. **文字与观看分流**：字幕优先，必要时按需 ASR/画面证据；带时间戳、缺口和来源版本。不要默认整库下载或全部送模型。
6. **个性化发现**：可借用 bilibili-discovery 的独立审阅/反馈实验；规则可检查、可关闭，探索不以强度和数量为目标。

## 文档维护规则

功能或接口变更时同时更新本页状态表、API 契约/示例、相关架构决策及部署说明。已部署、代码已实现、单元通过、真实账号通过和设备通过必须分别记录；来源调研保留原核查日期，不自动变成当前事实。不要把私人报告、账号列表、Cookie 或密码复制进这些文件。
