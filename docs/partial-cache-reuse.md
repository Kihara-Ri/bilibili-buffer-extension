# 部分命中复用：只补缺口并拼出完整响应

> 对应实现位于 `src/playback-cache.js` 与 `src/playback-observer.js` 的 `loadPlayerRange` 路径。
> 本文只描述这次新增的“部分命中”能力；完整命中的键、SIDX 时间映射、XHR/fetch 契约与容量回收规则见
> [playback-cache-design.md](./playback-cache-design.md)。

## 1. 要解决的问题

原实现只有两种结果：

1. 请求范围被驻留字节**完整覆盖**：直接返回本地 206。
2. 只要范围内存在一个缺口：整条请求判定为未命中，交给 `loadRange` 从网络下载**整个范围**（或退回浏览器原生请求）。

预热是按块写入的，播放器请求的范围又常与预热窗口错位。于是经常出现这种情况：

```text
驻留：[0, 1 MiB) + [2 MiB, 3 MiB)
播放器请求：bytes=0-3145727   （0 ~ 3 MiB）
旧行为：整段 3 MiB 重新下载，已经缓存的 2 MiB 被浪费
```

本次目标：**范围内已有的字节直接复用，只下载缺失的缺口，再拼成一条完整、经过校验的响应。**

## 2. 方案

### 2.1 缺口规划（`playback-cache.js`）

`coverage(entry, start, end)` 把请求范围拆成两类：

- `parts`：已驻留字节，按块起点排序后裁剪到 `[start, end)`；
- `gaps`：未被任何驻留块覆盖的半开区间。

`partialPlan(url, range)` 在此之上做守卫：

- 只接受单段 `bytes=a-b` / `bytes=a-`，与 `match()` 的范围语法一致；
- 总长必须已知，且 `end <= entry.total`；
- 单次重组长度不超过 `MAX_REASSEMBLY`（16 MiB）；
- 缺口数量不超过 `MAX_GAPS`（32）；
- 没有缺口时返回 `null`（完整命中由 `match()` 处理）；
- 请求范围内没有任何驻留字节时也返回 `null`，走旧的整段路径——只有真的复用了字节才算“部分命中”。

没有驻留覆盖时，网络看到的就是完整请求范围，行为与旧的“整段 `loadRange`”一致；有驻留覆盖时，网络只会看到缺口。

### 2.2 快照，而不是视图

驻留字节在规划阶段就用 `Uint8Array.prototype.slice()` **复制**成快照，而不是持有 `subarray` 视图。

原因是缺口下载是异步的：在这段时间里，容量回收、总长变化或条目替换都可能移除驻留块。虽然当前实现只修改块列表、不写回 `bytes`，但一旦将来有任何“覆盖式写入”，视图就会让待交付响应被悄悄改写。复制让“已规划的内容”与缓存生命周期解耦。

`MAX_REASSEMBLY = 16 MiB` 同时约束三项内存：驻留快照、缺口正文、最终输出，三者之和不超过约 2 倍上限；开放结尾请求不会把整部视频留在页面里。超限时不做部分拼接，交还原路径。

### 2.3 只对缺口发起网络请求

适配器在“范围内确实有可复用字节”时，不再对未命中调用 `loadRange(url, 原范围)`，而是：

```js
plan.gaps.map(([from, to]) => loadRange(url, `bytes=${from}-${to - 1}`, signal))
```

- URL 一律使用播放器请求的原始地址（完整查询串、签名不变），不使用预登记地址之外的任何主机。
- 每个缺口都进入 `loadPlayerRange`，因此沿用同一条去重键 `url|start|end`、同一套并发下载器、取消和页面世代保护。
- 缺口下载完成后由 `loadPlayerRange` 按既有规则写入缓存，未命中的部分不会阻塞后续请求。

### 2.4 校验与拼接（`assemble`）

`assemble(plan, results)` 只有在全部缺口都通过校验时才产出响应：

1. 结果数量与缺口数量一致；
2. 每个缺口的 `start` 与规划边界一致；
3. 每个缺口的正文长度恰好等于缺口长度；
4. 每个缺口的 `total` 是安全整数且与规划总长一致。

任何一项不满足都返回 `null`，适配器随即回退浏览器原生请求。**不存在“先交付半条响应、稍后再补另一半”**：要么拿到完整可拼接的数据，要么整条走原路径。

### 2.5 计数与调度

- `stats.partialHits` / `stats.partialHitBytes` 单独统计部分命中与复用的驻留字节；完整本地命中仍只记在 `hits` / `hitBytes`，互不污染。
- 各缺口把原需求范围作为父范围传给 `loadPlayerRange`，统一锚点为父范围末端；新的向后 seek 允许锚点回退，不能用单调钳制隐藏真实播放位置变化。
- 一处缺口失败即取消其余缺口，避免原生回退后重复下载；清空缓存也取消在途缺口。页面统计将完整命中与部分复用字节相加，但底层两类计数仍独立。

## 3. 边界与回退

| 情况 | 行为 |
| --- | --- |
| 完整覆盖 | 原有 `match()` 直接返回，不触发部分规划 |
| 部分覆盖且缺口可拼接 | 只下载缺口，校验后拼成完整 206 |
| 无驻留覆盖（范围内无任何可复用字节） | 不做部分规划，直接沿用原整段 `loadRange` 流程 |
| 超过 16 MiB 或缺口多于 32 个 | 不做部分拼接，交还原路径 |
| 缺口下载失败、返回空、长度不符或总长不一致 | 整条回退原生请求，不返回半成品 |
| 请求取消 / 页面切换 | 沿用原取消与世代检查，不交付旧字节、不回退原请求 |
| 未安装 `loadRange` | 完全保持原有适配器行为 |

## 4. 验证

先写测试并确认失败，再改实现。新增用例集中在 `tests/playback-partial-cache.test.mjs`，既验证适配器返回的字节，也验证真实调用链只请求了缺口：

| 验收项 | 证据 |
| --- | --- |
| fetch 只请求缺口并返回完整拼接正文 | `fetch 部分命中只请求缺口并返回完整拼接正文` |
| 缺口下载期间回收不污染快照 | `缺口下载期间发生回收也不能污染已快照的缓存字节` |
| 超限不做部分拼接 | `超过单次重组上限时不做部分拼接，交还原请求路径` |
| 缺口失败 / 总长不一致 / 缺一个缺口都不交付半成品 | `缺口失败不交付半成品…`、`缺口返回的文件总长…`、`两个缺口只补齐一个…` |
| 取消与世代保护 | `部分命中期间取消不回退原请求…` |
| 无覆盖时行为不变 | `无驻留覆盖时保持整段 loadRange 行为`、`范围内无驻留字节时不做部分规划…` |
| XHR 只请求缺口并交付拼接 ArrayBuffer | `XHR 部分命中只请求缺口并返回拼接后的 ArrayBuffer`、`XHR 缺口失败回退原生 send…` |
| 真实 `loadPlayerRange`/下载器只发出缺口 Range | `观察器 fetch 链路…`、`观察器 XHR 链路…` |
| 缺口失败后回退完整原范围 | `观察器网关失败后回退完整原生范围请求` |

复现命令：

```bash
npm test
npm run check
```

全部用例为 Node VM 级测试，不启动浏览器、不访问真实 B 站线路，也不使用用户浏览器配置。

## 5. 非目标

- 不改变完整命中的匹配规则、SIDX 时间映射、容量回收和黄色进度绘制。
- 不改变全局并发预算与节点选择逻辑（`playback-network.js` 未修改）。
- 不跨签名 URL、跨 CDN 主机或跨清晰度复用正文；键仍是完整 URL。
- 不把部分命中伪装成完整命中：只要补不齐就整条回退，不返回不完整数据。
