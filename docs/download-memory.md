# 下载工作内存与背压

- 在线：`playback-network.js` 在发起请求前按「两份请求长度 + 每路 512 KiB 救援余量」预留工作字节，同一实例上限 64 MiB。超过则按优先级等待；取消、导航、失败均释放/唤醒。单个范围仍最多 16 MiB。
- 部分拼接：缓存快照、缺口结果与拼接输出按两倍原范围预留，同页总上限 32 MiB；满额不做部分拼接，改走受在线字节准入约束的整范围路径。
- 驻留缓存：候选先参加回收，只复制最终留下的块，避免先复制再腾空间；默认驻留上限仍为 128 MiB。
- 离线：每轨道 16 MiB 窗口包含正在下载、乱序完成和等待事务提交的数据。只有 `onCommit` 成功才释放窗口；慢首块或慢磁盘会对后续网络请求产生背压。范围描述惰性生成，不为整个长文件预分配数组。每块至多 2 MiB、并发至多 32，并受窗口容量进一步约束。
- 离线首次错误取消同轨请求、唤醒窗口等待者；不把接收量算作落盘量。并行音视频最多两个轨道窗口；Blob 构造/浏览器内部可能有额外副本。

这些是插件工作缓冲的**准入/所有权边界**，不是整个 Chrome 进程的 RSS 保证：播放器持有的已交付 Response/ArrayBuffer、原生回退、Blob 内部拷贝、GC 未及时回收的对象以及浏览器网络缓冲不计入上述数字。不能把几个上限之和宣传成浏览器物理内存峰值。

验证：`tests/download-memory.test.mjs` 覆盖慢首块、慢落盘、落盘失败、外部取消、多在线任务、完整字节与部分拼接总预留；`tests/run-existing-memory-probe.mjs <pid> <tab>` 在用户现有 Chrome 检查六个大范围任务发生排队且 reset 后预留归零。探针是受控正确性测试，不是物理堆内存测量。
