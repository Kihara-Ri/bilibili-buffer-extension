# Popup 实时稳定性设计与实现（2.6.2）

## 1. 目标与边界

本轮处理播放进度条外观难理解、速度换行与跳动、片库悬停闪烁、已缓存数字回退、多任务排序/徽标互相覆盖，以及保存/删除样式和动作反馈。保持 2.6.1 的黄色来源保留与播放器缓存复用链路不变，不新增权限。

## 2. 先追执行链，再修表现

下载 Range → `offscreen.js` 接收/连续提交 → IndexedDB → `CACHE_PROGRESS` → background 徽标/转发 → Popup 消息与轮询 → 片库/主按钮。

原来的 UI 刷新会清空并重建列表，浏览器每次都失去旧的按钮、SVG、hover/focus 和 Tooltip 状态。只调整动画时长或加防抖不能解决节点身份丢失。列表还按会被每个心跳更新的 `updatedAt` 排序，两个并行任务自然轮流排在前面。

数据方面，接收到内存的字节包含尚未提交或要在重试中撤销的部分，不能直接解释成“已缓存”。协调器准备事务时提前增加 resume 水位，也存在事务尚未完成、另一轨又发出快照的交错窗口。共享徽标则被各任务自己的百分比覆盖，最后到达的事件获胜。

## 3. 按 ID 更新，不反复建 UI

- `libraryItems` 保存业务 ID → DOM 的映射，事件处理器从节点读取最新记录。
- 只在增删或稳定排序键变化时移动节点，普通进度 tick 更新变化的文本、属性和样式。
- `createdAt` 持久化，旧记录用 ID 确定性兜底；`updatedAt` 不再参与排序。
- `newerTask` 比较 `runStartedAt` 和 `updatedAt`，防止较早查询晚返回覆盖新消息。删除记录设置墓碑，旧消息/查询不能复活行；后续真正新任务可用新时间戳进入。
- 保存/删除的 pending 独立于任务数据，周期刷新不重新启用按钮。

保存和删除均为 32×32 按钮、纯图标、同一列对齐，保留 title 和明确的 aria-label。下载箭头在 hover/focus 时只向下播放一次；删除盖子轻微抬起。减少动态模式禁用箭头动画和过渡，不用无限循环动效吸引注意。

## 4. 确认落盘与进度语义

`downloadedBytes` 表示接收量，`resumeBytes` 表示连续断点，新增 `committedBytes` 表示对外可承诺的确认落盘量。

一次提交的顺序：

1. 暂存当前轨的新断点，构造包含新水位的数据库快照。
2. 在同一 IndexedDB 事务内写入 Blob 分块和元数据。
3. 等待事务完成，然后提高内存中的 confirmed 水位，再广播。
4. 如果事务失败，恢复原断点；此时外部从未收到虚假的已缓存增长。

事务悬而未决时，其他轨或新的接收事件可以更新瞬时速度和在途量，但广播中的 `committedBytes` 仍保持旧确认值。撤销在途数据也不会减少已确认值。渐进下载与兼容顺序下载路径同样填写该字段。

`taskProgress` 在下载阶段把原始接收比例换算为确认落盘比例；`committedBytes` 缺失时兼容旧记录的安全断点。合并、音频提取等阶段保留其自己的进度语义，不用下载字节算处理进度。

这不是用历史最大值掩盖问题：真正开始新一代下载、重新选择媒体、数据失效或处理后文件大小变化，仍可能重置/改变数字，并由任务世代、阶段和状态文案解释。

## 5. 速度、布局与多任务

`sampleSpeed` 按样本时间做指数平滑，相同时间戳的重复轮询不会重复加权；停止、等待或过期样本归零。进度使用浮点比例与 transform，不先把宽度量化为整数百分比。数字采用等宽数码，速度和单位 `nowrap`，主按钮为标签与数值预留独立空间，避免单位把布局挤到下一行。

background 不再直接使用每条消息的百分比写徽标，而是从 IndexedDB 任务集合加最新快照派生：一个活动任务显示进度；多个显示 `N↓`，标题解释任务数；无活动任务后显示完成或错误状态；删除后重算。Promise 队列只防 API 调用乱序，任务真相不依赖 SW 内存，重启从数据库恢复。

## 6. 播放外观与配置竞态

外观区常驻提供：示意进度条与图例、已播放颜色、单独标出提前加载、六种预设和自定义色、恢复默认。示意条明确标注“不代表当前视频进度”。关闭颜色区分只令提前加载段显示灰色，不关闭提前加载本身。

配置更新先乐观渲染，再串行写入；修订号阻止旧轮询/旧请求覆盖最新操作。测试进一步复现了连续两次保存失败会回到上一次失败的乐观值：现在单独保留 `confirmedAssistConfig`，立即回到最后成功保存的配置，不依赖下一次轮询来修正。播放主开关也通过同一配置队列，避免和配色保存互相覆盖。

## 7. 自动化验收

```bash
npm run check
npm test
PLAYWRIGHT_MODULE=/绝对路径/playwright/index.mjs npm run test:popup
PLAYWRIGHT_MODULE=/绝对路径/playwright/index.mjs npm run test:extension
```

- `task-presentation.test.mjs`：确认字节、旧快照、真实新世代、处理阶段、速度与多任务规则。
- `download-watermark.test.mjs`：运行真实协调器函数、替换 I/O 与时钟，控制事务悬置/失败/成功，复现跨提交窗口，确保未提交的字节不被发布。
- `run-popup-stability.mjs`：Chromium 加载真实 Popup；连续更新期间同一 DOM、固定顺序、实际 hover 一次动画、焦点保留、保存 pending 保留、32×32 对称按钮、B/s、KB/s、MB/s、GB/s 四种速度单位不换行且不重叠、逐帧确认进度有中间插值且不倒退、确认缓存量不随在途回滚减少、配置恢复默认/开关/键盘/连续失败回退、保存失败恢复、删除后旧数据不复活、减少动态。
- 同一运行器执行 background 与 offscreen 浏览器消息链路，校验双任务徽标及完成/删除转移、下载快照水位，以及完整双轨合并和音频提取回归。
- `run-playback-extension-smoke.mjs`：生产包真实加载与 runtime.reload；刷新受测页面，校验注入模块 SHA-256 和命中行为，并确认持久化完成任务的徽标在重启后恢复。
- 截图位于 `.pi/verification/popup-stability/`；测试报告用节点、事件和几何断言作主要证据，截图只作视觉补充。

测试工具本身也修正了两个陷阱：MV3 SW 禁止动态 import，所以恢复测试从扩展页面准备同源数据库；Chromium 会向 unpacked 写入 `_metadata`，测试结束需清理此残留，才能与生产 zip 逐文件一致。

这些是受控本地浏览器/消息夹具，不宣称已经在用户当前登录会话或所有 B 站视频上实测。

## 8. 防止后续重复犯错

权威 `../AGENTS.md` 增加实时 UI 强制约定，运行 `node ../tools/sync-agents.mjs` 同步到两个扩展。公共说明为 `../docs/realtime-ui-stability.md`：列出重建节点、动态 key、更新时间排序、过期响应、非原子水位、共享徽标的反模式，并要求 hover/focus/pending、多任务与失败分支的浏览器检查。

这些规则与自动测试降低重复引入问题的风险，不能承诺未来 AI 永远不犯错。未改动原有未提交功能的实现，也未把无关内容回滚。
