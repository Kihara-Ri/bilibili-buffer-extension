# 下载工作内存与背压

> 适用版本：v2.16.1 后的工作区 · 2026-11-22
> 对应实现：`src/playback-network.js`、`src/playback-cache.js`、`src/download-budget.js`、`src/range-downloader.js`。

本文列出插件自己的工作缓冲在各环节的字节上限。

| 环节 | 上限 | 约束方式 |
| --- | --- | --- |
| 在线在途正文 | 约 17 MiB | 最多 34 个尝试（32 普通 + 2 急需救援） × 每片至多 512 KiB，由分片引擎槽位直接约束 |
| 单个播放器请求 | 16 MiB + 一份输出 | 驻留快照与缺口正文写进同一个最终缓冲 |
| 页面驻留缓存 | 128 MiB | 超出按[播放位置感知顺序](playback-retention.md)回收；候选先参加回收，只复制最终留下的块，避免先复制再腾空间 |
| 离线任务 | 2 个 | Offscreen 排队分配，任务在取源、传输和收尾期间持有名额，等待退避时归还 |
| 离线媒体连接 | 8 路 | 探针、Range、对冲和顺序回退共用。自适应页稳定播放时至多 2 路。全速档稳定播放时可用空闲的共享连接。任何页面缓冲告急时暂停发新请求 |
| 离线工作正文 | 24 MiB 合计 | 按请求范围预约，覆盖在途、乱序完成、待提交及镜像暂存。顺序流使用 4 MiB 写入窗口 |
| 离线每轨窗口 | 16 MiB | 避免慢首块让一个轨道占满共享额度；对冲正文额外计入共享 24 MiB |

## 离线背压

- 正常分块在 IndexedDB 事务成功后释放正文额度。失败或取消时，先结束在途请求及已开的事务，再归还丢弃正文的额度。连接额度在响应消费或取消后归还。
- 每块至多 2 MiB、并发至多 32，并受窗口容量进一步约束：`并发 ≤ 窗口 ÷ 块大小`。
- 空闲工作者用共享预算中的余量发起队头对冲。两份正文分别计入同一额度，败方在收尾后释放。镜像也只在有余量时借用字节，写入完成或失败即归还。
- 范围描述惰性生成，不为整个长文件预分配数组。
- 首次错误取消同轨其余请求并唤醒窗口等待者。接收量与确认落盘量分别记录。

## 这些数字不代表什么

这是插件工作缓冲的**准入与所有权边界**，不是整个 Chrome 进程的内存保证。以下都不计入：播放器持有的已交付 Response / ArrayBuffer、原生回退请求、Blob 构造和浏览器内部的副本、GC 尚未回收的对象、浏览器网络缓冲。不能把几个上限相加宣传成内存峰值。

## 验证

- `tests/download-memory.test.mjs` 覆盖离线慢首块、多个窗口共用额度、落盘失败与外部取消。
- `tests/run-playback-extension-smoke.mjs` 使用生产包和受控线路验证播放让行、已开始请求被取消及续传完成。
- `tests/playback-network.test.mjs` 覆盖在线槽位与取消后立即归还。
