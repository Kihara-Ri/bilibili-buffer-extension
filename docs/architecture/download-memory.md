# 下载工作内存与背压

> 适用版本：v2.14.4 · 最后核对：2026-10-25
> 对应实现：`src/playback-network.js`、`src/playback-cache.js`、`src/range-downloader.js` 的 `downloadByteRanges`。

本文列出插件自己的工作缓冲在各环节的字节上限。

| 环节 | 上限 | 约束方式 |
| --- | --- | --- |
| 在线在途正文 | 约 16 MiB | 最多 32 个尝试 × 每片至多 512 KiB，由分片引擎槽位直接约束 |
| 单个播放器请求 | 16 MiB + 一份输出 | 驻留快照与缺口正文写进同一个最终缓冲 |
| 页面驻留缓存 | 128 MiB | 超出按[播放位置感知顺序](playback-retention.md)回收；候选先参加回收，只复制最终留下的块，避免先复制再腾空间 |
| 离线每轨窗口 | 16 MiB + 至多 2 个对冲分块 | 包含正在下载、乱序完成和等待事务提交的数据；队头对冲的重复请求另计，至多 2 × 2 MiB |
| 离线并行轨道 | 2 个窗口 | 视频与音频各一个 |

## 离线背压

- 窗口只有在 `onCommit`（IndexedDB 事务）成功后才释放。慢首块或慢磁盘会让后续网络请求等待，而不是无限堆积。
- 每块至多 2 MiB、并发至多 32，并受窗口容量进一步约束：`并发 ≤ 窗口 ÷ 块大小`。
- 窗口满时空闲工作者可对队头分块发起对冲（见[完整缓存 · 4.2](offline-cache.md#42-range-分块并发)）。对冲不占新的窗口额度，因为同一分块只会有一份落盘；胜负分出后败方的正文立即丢弃。
- 范围描述惰性生成，不为整个长文件预分配数组。
- 首次错误取消同轨其余请求并唤醒窗口等待者；接收量不算作落盘量。

## 这些数字不代表什么

这是插件工作缓冲的**准入与所有权边界**，不是整个 Chrome 进程的内存保证。以下都不计入：播放器持有的已交付 Response / ArrayBuffer、原生回退请求、Blob 构造和浏览器内部的副本、GC 尚未回收的对象、浏览器网络缓冲。不能把几个上限相加宣传成内存峰值。

## 验证

- `tests/download-memory.test.mjs`：离线慢首块、慢落盘、落盘失败与外部取消；
- `tests/playback-network.test.mjs`：在线槽位与取消后立即归还。
