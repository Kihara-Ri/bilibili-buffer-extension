# 弹窗

> 适用版本：v2.14.2 · 最后核对：2026-10-25
> 对应实现：`popup.html`、`popup.css`、`src/popup.js`、`src/task-presentation.js`、`src/popup-snapshot.js`、`src/cache-size.js`。
> 实时刷新规则的来历见 [2.6.2 弹窗稳定性设计记录](../history/2.6.2-popup-stability.md)。

弹窗只负责交互，不承担持续下载：它关闭后 Document 就被销毁。重新打开时，界面先用 Service Worker 存在 `chrome.storage.session["popupPageSnapshotsV1"]` 里的页面快照立即渲染，再异步刷新。

## 1. 结构

界面按「正在做什么」与「偶尔才调」分层。

### 1.1 当前视频（一级页签）

- **视频信息**：标题、UP 主、时长、分 P。
- **内容**：「视频 / 仅音频」分段控件。大会员账号在同一行右侧挂一枚「大会员」小标记（悬停看声明 / 返回档位对照），不再写「已登录大会员」一句话。
- **画质**：一根滑杆（参照 ChatGPT 的推理强度控件），左低右高，默认在最右的最高可选档。多数人只要最高画质，不再给每一档同样大的卡片。
  - 上方居中是完整档位名与预计体积，下方两端是最低 / 最高档的短名；读屏通过 `aria-valuetext` 读出「档位、体积」。
  - 拖动、方向键、Home / End 都由原生 `<input type="range">` 提供；`input` 时只更新界面，`change`（松手或按键结束）才发 `SET_POPUP_SELECTION` 存回后台。
  - 当前账号拿不到的更高档位（需要登录或大会员、且高于可选最高档）画成杆尾的斜纹锁定段，最高档短名用粉色；range 只铺在可选段上，拖不进去。大会员账号缺的档位是视频本身没有，杆上不画。
  - 几何：N 个档位等距排在 [拇指半径, 宽 − 拇指半径]，range 宽 = 拇指 + (总宽 − 拇指) × 可选比例，所以拇指与装饰档位点严格重合；填充用 `clip-path` 裁出长度，不改布局。
  - **顶档**（选中整根杆的最右一档、上面没有锁定段）：杆身变成由浅到深的海，水面两层错位的浪缓缓向右推（`::before`），水里有气泡往上冒（`::after`），拇指里是一只漂流瓶，档位名用海的蓝色渐变。未登录 / 非大会员时可选最高档上面还有锁定段，不算顶档。动画只动 `transform`，节点常驻、只切 `data-top`，轮询刷新不会让它重启；下载中整根杆变淡并暂停，「减少动态效果」时静止。
  - 档位点与两端名称只在档位集合变化时重建，其余每次刷新只改属性与文字。下载中不能换档。仅音频模式下画质隐藏，改显示「音质」摘要。
- **账号说明**：画质下方一行小字，只在影响「这次能选什么」时出现——未登录时写「登录后可选 1080P60」并在右侧给出「去登录 ›」（新标签打开 B 站登录页，不需要新权限）；已登录非大会员且杆尾有大会员档时写「4K 需要大会员」；读取出错或登录态受限用警示色，仅音频模式也保留。
- **主按钮**：承载缓存状态——空闲时是「缓存」，下载中变成进度条并显示已缓存字节与速度，完成后是「已缓存」。暂停（「已暂停 N%」）与出错（「继续缓存 N%」）沿用下载中的进度样式和已缓存字节，不再变回粉色主按钮；点主按钮即可继续。右侧并排一个圆形图标按钮（不能把 `<button>` 嵌进 `<button>`）：下载中是「暂停」，暂停或出错时是「继续」，只在模式变化时换图标。
- **漂流瓶元素**（呼应名字与工具栏图标）：主按钮外形仍是圆角矩形——瓶形放不下标题、字节、速度与圆钮，进度也会被曲线切掉。只在两处点到为止：
  - 进度填充的右缘是一道缓慢起伏的水波，暂停 / 出错时水面停住，「减少动态效果」时静止。填充改用 `translateX` 平移（`scaleX` 会把波纹压扁），实色层与波纹层都不透明、交界重叠 1px，半透明由父层 `opacity` 加静态渐变遮罩统一给出，交界没有拼接缝。波纹只对 `::after` 做 `translateY` 循环，进度刷新不会让它重启。
  - 空闲「缓存」前是一个空瓶，「已缓存」前换成塞好瓶塞、装着信的瓶子；下载中不显示，避免分散对数字的注意。字形是 `#button-label` 的兄弟节点，文字刷新不会抹掉它。
- **提前加载**：标题行有状态标签、「详情」展开键和开关。概览只有三个数字：网速、已就绪、已命中。「详情」展开两列读数：播放器缓冲、卡顿（次数与累计时长）、缓存占用 / 128 MB、加速请求（含「救援」次数）、最近节点；「异常」一行（交还原生 / 预热失败 / 隔离节点）只在出现时显示，并用警示色。

提前加载状态标签只依据 5 秒内的新鲜统计：

| 状态 | 条件 |
| --- | --- |
| 已关闭 | 开关关闭 |
| 等待视频播放 | 统计过期，或还没有活动轨道 |
| 连接不稳定，自动重试中 | 有预热失败、当前没有在途预热、前方也没有就绪内容 |
| 正在提前加载 | 有在途预热分片 |
| 前方已就绪 | 当前位置之后有连续着色的内容 |
| 已开启 | 其他开启状态 |

### 1.2 片库（一级页签）

- 顶部显示数量与总体积。
- 每行：封面（`http` 地址换成 `https`）、标题（点开原视频，已缓存时自动本地播放）、「状态 · 体积 · UP 主」（截断时只截掉最次要的 UP 主）、未完成时一条细进度条。
- 右侧固定两个 32×32 动作：下载中「暂停」/ 暂停或出错时「继续」/ 完成时「保存」，以及「删除」。
- **继续**走 `RESUME_CACHE`，不需要打开原视频。
- **删除**不弹确认框：行立即隐藏，提示条给出 6 秒「撤销」；超时或弹窗关闭（`pagehide`）才真正发出 `DELETE_VIDEO`。下载中的任务先暂停，撤销时再继续。撤销期内在「当前视频」对同一缓存内容（同画质、同编码，或仅音频）点「缓存」等同于撤销：取消待删除并从原进度续传。否则后台会续传那条被暂停的记录，界面仍把它当待删除隐藏（按钮转一圈又变回「缓存」），到点后删除还会把刚恢复的任务删掉。

- **评价邀请卡片**（片库顶部，`#review-card`）：只在用户用出价值后出现——片库里已完成 ≥ 2 个、首次打开弹窗已满 24 小时、此刻没有任务在下载、不在推迟期。三个动作：「去评价」（新标签打开商店评价页并记为已评价）、「以后再说」（14 天后再出现，推迟 2 次后等同不再提示）、「不再提示」。状态存 `chrome.storage.local["reviewPromptV1"]`，逻辑在 `src/review-prompt.js`（纯函数，有单测）。合规边界：不奖励、不按情绪筛选、可永久关闭；改文案或条件前先对照 Chrome 网上应用店的用户评价政策。卡片是固定节点，只切换 `data-open` 与 `inert`（grid 行高 0fr→1fr 展开收起，减少动态偏好下无过渡），轮询刷新零 DOM 变更。

### 1.3 设置（齿轮打开的二级视图）

覆盖页签，用返回按钮或 Esc 回到原页签。打开设置时隐藏重复的页脚，保证整页在 600px 以内。

- **进度条外观**：一条示意预览 + 图例、已播放颜色、「单独标出提前加载」、六种预设与自定义颜色、恢复默认。说明文字明确「只改颜色，不影响提前加载本身」。
- **浏览器自检**：始终显示结论；失败时列出不可用的能力，可以「重新检测」。另有固定文案提示到 `chrome://extensions` 确认扩展没有被停用——被停用的扩展不运行任何代码，自检发现不了这一点。
- **关于**：版本、GitHub、「在商店评价」入口（常驻，点开即记为已评价）、隐私说明。

自检失败时，主视图顶部出现一条提示（「查看」跳到设置），齿轮带红点。每个主视图底部常驻「缓存与登录态只保存在本机 · 隐私说明」——Chrome Web Store 2026 年的政策要求安装后也要显著披露数据处理方式。

### 1.4 尺寸与外观

- **不出现滚动条**：Chrome 弹窗高度封顶 600px，Windows 上内容超高（微软雅黑行高更大、画质折成两行、展开「详情」）会出现 15px 的经典滚动条并把内容向左挤。`html` 用 `scrollbar-width: none` 与 `::-webkit-scrollbar { display: none }` 隐藏滚动条，超出部分仍可滚轮 / 键盘滚动；「详情」读数行距同时收紧 2px 以降低超高概率。

- 整页（含展开的详细数据）不得超过 Chrome 弹窗的 600px 高度上限，否则出现滚动条；`tests/run-popup-stability.mjs` 与 `npm run store:assets` 都会检查。弹窗固定 360px 宽。
- 跟随系统明暗：浅色「雾白」与深色「夜航」两套色板都定义为 `popup.css` 的令牌，深色只在 `prefers-color-scheme: dark` 中重定义令牌，组件不写死颜色。分隔用发丝线，「详细数据」是点线引导的读数表，数字用等宽数位。隐私说明页使用同一套色板。
- 页眉的名称与诗句连读，规则见[构建与发布 · 名称的呈现](../development/build-and-release.md#33-名称的呈现诗句连读)。

### 1.5 键盘与无障碍

- 页签使用 ARIA `tablist` / `tab` / `tabpanel`，支持点击、左右方向键、Home、End。
- 「视频 / 仅音频」、颜色预设都是 `radiogroup`：方向键移动并选中，Home / End 到两端。画质是原生 range，键盘行为相同。
- 提前加载开关是 `role="switch"`；状态标签是 `role="status"` 并 `aria-live`。

## 2. 实时刷新规则

下载进度、提前加载统计都会高频刷新。以下规则保证刷新不破坏交互：

- **按业务 ID 复用节点**：`libraryItems` 保存「视频 ID → DOM」映射，普通 tick 只更新变化的文本、属性和样式；只有增删或稳定排序键变化才移动节点。hover、focus、Tooltip 和动画因此不会随刷新重启。
- **稳定排序**：片库按 `createdAt` 排序、ID 兜底；`updatedAt` 每个心跳都在变，不参与排序。
- **挡住过期数据**：`newerTask` 比较 `runStartedAt` 与 `updatedAt`，较早发出却较晚返回的查询不能覆盖新消息；删除的记录设墓碑，旧消息不能让它复活。
- **pending 独立于数据**：保存、删除、暂停等异步操作的 pending 状态不随周期刷新重置。
- **只承诺确认落盘的量**：「已缓存」取 `committedBytes`（见[完整缓存 · 三种水位](offline-cache.md#44-连续提交与三种水位)），在途数据回滚不会让数字倒退。
- **速度平滑**：`sampleSpeed` 按样本时间做指数平滑，同一时间戳的重复轮询不重复加权；停止、等待或过期时归零。
- **布局不抖**：数字用等宽数位，数字与单位不换行；进度条用浮点比例和 `transform`。
- **徽标由任务集合派生**：后台从 IndexedDB 任务集合加最新快照计算徽标——一个活动任务显示进度，多个显示 `N↓`，无活动任务时显示完成或错误；Service Worker 重启后从数据库恢复，不依赖内存。
- **配置串行保存**：颜色和开关先乐观渲染再串行写入，修订号挡住旧响应；保存失败回到最后一次**确认成功**的配置（`confirmedAssistConfig`），而不是上一次失败的乐观值。
- **减少动态**：尊重 `prefers-reduced-motion`，禁用箭头动画与过渡。

这些规则来自上级目录 `AGENTS.md` 的「实时界面稳定性」一节。
