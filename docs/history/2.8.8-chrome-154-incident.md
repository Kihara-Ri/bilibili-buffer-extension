# Chrome 154 后「插件不可用」故障记录（2.8.8）

> **历史记录，内容冻结。** 本次故障催生的版本门禁与运行期自检见[浏览器版本兼容与自检](../development/browser-compat.md)。
> 文中的「共享下载预算」「租约」已在 2.8.13 整体移除。

## 1. 现象

2026-09-23，Chrome 升到 154 后插件完全不可用：弹窗打不开、网页侧没有加速、图标点不动。

## 2. 结论

三条都是可复核的事实，不是推测：

1. **扩展代码与 Chrome 154 兼容。** 用与本机 Chrome 同构建的 Chrome for Testing 154.0.8037.57 实际加载扩展验证：MAIN / ISOLATED 注入、播放加速、页面缓存命中、Offscreen 离线下载、IndexedDB 落盘、下载预算租约、DNR 规则集全部正常；仓库四个浏览器套件在 154 上全绿。
2. **真正原因是扩展在 Chrome 里被停用了。** 用户配置里 `extensions.settings.ppoagkhgdcfchiodhgadpenibndbnhcj` 的 `disable_reasons = [1]`（`DISABLE_USER_ACTION`），安装形态是解包安装（`location = 4`）。扩展一旦被停用，内容脚本、DNR 规则、Service Worker 全部不运行，表现就是「插件没反应」。同为解包安装的 `b站延拓` 没有出现在受影响的记录里。**没有证据能区分这次停用是 Chrome 的提示流程造成还是手动点击造成**，但恢复方式相同：在 `chrome://extensions` 打开开发者模式并重新启用。
3. **为什么没人提前发现。** 浏览器验收跑在 Playwright 自带的 Chrome for Testing 153 上，比用户的 154 低一档；而覆盖弹窗与离线下载的 `npm run test:popup` 自 2026-09-22 引入共享下载预算后就一直是失败的（见第 3 节）。两件事叠加，「验收全绿」与「插件不可用」可以同时成立。

## 3. 浏览器验收夹具与后台实现漂移

2.8.2 引入跨标签与离线共享请求预算后，`tests/offscreen-integration.mjs` 与 `tests/offscreen-merge-integration.mjs` 的消息桩仍只回 `{ ok: true }`。下载器拿不到 `lease`，一直等到 15 秒预算超时，套件在「下载完成」处静默超时。浏览器套件不在 `npm test` 里，这个红灯持续存在而无人察觉。

当时的修法是让夹具**复用生产状态机**而不是复制一份策略：夹具直接调用 `src/request-budget.js` 的 `transitionBudget`，只提供消息入口，并断言「申请过租约」与「正文结束后归还租约」。2.8.13 删除共享预算后，这些夹具与断言随之删除；留下的教训是「夹具必须复用生产实现」。

## 4. 由此新增的机制

- `browser-compat.json` + `scripts/check-browser-compat.mjs`：本机 Chrome 跑到未验收的主版本时 `npm run check` 直接失败；
- `npm run test:chrome`：在与本机同构建的 Chrome for Testing 上重跑全部浏览器套件；
- `src/health-check.js`：运行期能力自检，结论显示在弹窗设置里。
