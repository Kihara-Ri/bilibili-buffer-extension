# CDN 与缓冲恢复续审

日期：2026-10-27（Asia/Tokyo）。范围：当前未提交的 2.16.0 CDN 改动及与页面缓存、离线复用的整合。所有改动保留在本次聊天的隔离工作区，未覆盖主目录的并行工作，未发布。

## 已复现并修复

### 1. 清单更新可让旧镜像绕过校验

旧版每轮保留候选 URL 列表，但每次尝试又读取当前清单对象。移除旧备用地址后，从它生成的旧镜像不再属于新对象的 mirrors，校验分支直接跳过。复现中原头是 7，旧镜像返回同总长、全 255 的正文；错误字节确实进入 onPiece 缓存回调。

修复：每轮候选与校验绑定同一清单对象，在校验、等槽、读取、写缓存和拼装前核对归属。清单修订时整轮作废、限次重选；不记为 CDN 健康失败。新增 primary / backup 两个更新时机的失败回归及新清单健康候选成功交付的正向回归。独立复审确认重新调度后只写缓存一次，active / queued / blocked 均归零。

实现：[网络引擎](../../src/playback-network.js)。

### 2. 首次并发响应总长不一致仍能被拼装

两个分片同时在总长未知时启动，分别返回 4 MiB 与 8 MiB 的总长。每份响应按启动时的未知快照通过校验，原实现仍拼出响应，并把不一致字节写入缓存。此外，超过 Number.MAX_SAFE_INTEGER 的总长也被接受。

修复：拒绝不安全、非正的总长；每个分片交付前重新检查已确立的总长，拼装时再次核对。错误分片不能先写缓存。两条回归均已先观察失败。

### 3. 已驻留文件头让镜像救援始终不能启用

原实现只有引擎从位置 0 下载至少 1 KiB 时才建立身份；离线复用或原生初始化命中的头已在缓存里，规划器会跳过它，永不再下载 0。小于 1 KiB 的初始化请求、以及仅更换备用地址的清单修订也可能留下同类缺口。

修复：观察器把原地址连续驻留头和总长交给调度器。仅接受当前原地址组中的兼容来源，验证字节类型、长度和总长；不信任未经校验生成的镜像，不重复下载已缓存头。新增真实 cache + network + observer 的三条整合回归，HTTP 与离线服务作为外部边界替身。

实现：[观察器](../../src/playback-observer.js) 的 seedCachedReference 与网络引擎 seedReference。

### 4. 无 SIDX 时小数时长生成非法 Range

10 MiB、431.7 秒的无索引视频，码率估算实际生成了 `bytes=3145728-3234626.424600417`。该协议范围无效，可能导致最后一块预热反复失败。

修复：字节预算向下取整，既保留预算上限也保证 Range 整数。回归运行真实规划器与请求格式化器，检查实际发出的请求头。

### 5. 取消或切换后离线复用的迟到命中回填缓存

离线读取 await 之后，原命中分支直接写缓存和统计，没有重新判断取消、页面或开关状态。复现覆盖播放器取消、关闭后重开、导航三种情况。

修复：查询开始前记录页面与会话世代，命中/未命中返回后都核对取消、配置、页面、轨道和精确 URL 归属。切换会话后不写旧字节、不计旧命中、不以旧字节建立镜像身份。三条迟到命中回归均先失败后修复。

## 验证方式

- Node 回归覆盖协议校验、并发总长、真实缓存整合、生命周期、清单竞态；完整项目单测、语法/浏览器门禁、浏览器网络与双轨播放、生产扩展注入和包校验在交付前执行。
- 独立审查构造了缓存头与清单竞态复现；最后复审针对清单更新的拒绝和成功重选路径通过。
- 五项 CDN 续审针对调度器与复用边界。
- 本轮修复针对正确性与恢复边界，不宣称所有线路更快；首轮十场景性能数据保留在 [首轮验收](2026-10-26-cdn-recovery-validation.md)，不能当成本轮重新测速结果。

最终验证结果：

- `npm test`：321/321 通过。
- `npm run check`：123 个 JS 文件语法通过；Chromium 156.0.8078.4，浏览器版本门禁通过。
- `npm run test:network`、`npm run test:playback`：通过（真实 Chromium、受控网络、双轨解码与 seek）。
- 最终生产扩展注入与 runtime.reload：通过，普通视频与四种语言/列表路径均完成 MAIN/ISOLATED、fetch/XHR 命中、重载哈希及 SW 恢复验证。
- `npm run build`：发布包结构、图标、权限、开发入口隔离、ZIP 一致性通过。
- 真实匿名视频复验：显式语言页，实际阻断原线路 16 次后，通过真实 hw 镜像继续取回媒体；seek 从 721.05 秒推进到 741.14 秒，末尾原生回退 0、预热失败 0。此次约 1.56 秒等待包含启动/seek，并非零等待。

真实验收过程也暴露了一处脚本缺口：首次尝试在页面重定向时上下文被销毁；随后显式语言页虽播放成功，但页面内联对象没有预期 DASH 字段，导致故障注入实际命中 0 次，脚本最终正确报“未观察到真实镜像下载”。现已把原线路识别扩展为“内联清单 + 观察器实际记录轨道”，并在注入前要求非空主机集合、结束后要求阻断次数大于零。修复脚本后才得到上面的成功结果；前两次失败日志均保留在开发态目录，未算作通过。
