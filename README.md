面向海外网络环境的 Chrome Manifest V3 插件。它提供两条互补路线：播放提前加载将后续媒体分段保存在页面内存中，播放器的 XHR/fetch 请求完整命中时直接复用；离线片库则通过当前 B 站登录会话读取实际可用画质并完整缓存。默认选择账号可用的最高画质与同画质下码率更低的可播放编码；再次打开相同视频与分 P 时，可在原网页播放器中使用本地 Blob 或 MediaSource，保留控制条、倍速、进度与弹幕同步。

## 安装

1. 打开 `chrome://extensions/`。
2. 开启右上角“开发者模式”。
3. 选择“加载已解压的扩展程序”，选择本项目文件夹。
4. 打开标准 B 站视频页（`https://www.bilibili.com/video/BV...`）或带 `bvid` 的稍后再看页面，点击工具栏中的插件图标。

## 使用

- 面板按任务分为“缓存”“播放”“片库”三个页签，同一时间只展示一类内容；画质选择留在缓存页，播放提前加载开关和高亮颜色留在播放页，已缓存项目集中在独立片库页。可用鼠标点击，也可在页签上用左右方向键切换。
- “缓存内容”提供“视频 + 音频”和“仅音频”两种选择，默认前者并跨弹窗保存。选“视频 + 音频”时下载视频轨和音频轨并合并成一个 MP4；选“仅音频”时保留 B 站返回的原始容器与编码（Hi-Res 无损优先，其次是杜比全景声，最后是 AAC），不做任何转码。如果 B 站只返回单文件 MP4（没有独立音频轨），会先下载整段 MP4，再在本地无损抽出音轨并丢弃视频样本，与 yt-dlp 的 `-x` 行为一致；面板会提前标明“整段下载后提取音轨”。
- 选“视频 + 音频”后，在“缓存画质”中选择清晰度；首次打开默认选中 B 站返回的最高可用画质。“仅音频”时画质行隐藏，缓存大小改为显示将选中的音频类型与估算体积。
- 画质菜单只列当前账号实际返回轨道的档位，最高一项带“（最高）”标记；如果 B 站声明了但当前账号没返回（通常是大会员专属档位），登录提示会追加“N 档未返回”，把鼠标移到画质按钮上可以看到“B 站声明可用 / 当前账号返回 / 未返回”的完整对照。
- 缓存页显示当前画质的音视频总大小，切换画质时同步更新。下载前按码率和时长估算并标注“约”，取得完整大小后显示实际值。
- 缓存页不再展示编码选择；新任务自动选择同画质下 Chrome 可播放且码率最低的编码，减少需要下载的数据。
- 在线请求与预热共享多节点调度器：8 路起步、全局最高 32 路；真实播放缓冲不足 3 秒立即放开全局预算，不足 10 秒或吞吐低于播放消耗的 1.25 倍时，每 500 ms 可翻倍增援。每个急需请求每 256 KiB 分配一个普通工作者（受用户上限限制），救援共享全局预算；不再让 2 MiB 片段盲开 32 路。700 ms 无字节进展启动备用救援，首字节超时 3.5 秒、正文停滞 2.5 秒、单连接最长 10 秒。当前片段仍拆成 64 KiB 小块，便于局部重试；块数与并发数分开控制。真实 Chrome 对照实验与局限见 [并发验证报告](docs/concurrency-validation.md)。
- 播放页统计包含插件按需下载与预热的合计网速，已命中量表示播放器真正复用的数据；播放器缓冲与预热就绪分开显示，后者要求音视频在当前位置连续就绪。节点仅显示主机名，不展示签名地址。
- “播放”页提供提前加载开关，默认开启。取得播放器首个媒体范围后即开始预热：优先补初始化区和 SIDX，再按真实时间挑选播放位置前方的分段。兼容 fetch 和异步 GET、arraybuffer 类型的 XHR；完整命中可拼接/切片返回缓存，缺口走分块网络加速，适配或线路失败回退原始请求。全页驻留正文最多 128 MiB（另有在途和返回副本）；关闭会取消预热并清理驻留缓存。
- 黄色（沿用可配置的预热色，默认橙色）只表示当前音视频两轨的初始化区和完整媒体段都驻留、且按 SIDX 映射后的就绪时间交集。未播放区域的黄色优先于播放器灰色，播放器灰条跟上不会抹掉黄色；已播放进度保持正常。原生节点、滑块、点击和拖动不被替换。关闭颜色区分时仍显示缓冲范围，但统一为灰色。
- 保留原生进度条的章节分段、尺寸、圆角、悬停效果、小电视指示器及全部原生交互。插件只修改已播放颜色（默认蓝色，可自定义）和未播放区域的缓冲配色，不新增覆盖层或替代指示器，不修改播放位置。原生缓冲沿用播放器的灰色，插件缓冲可单独着色，未缓冲底色保持原样；未播放重叠区域保留插件黄色，已播放进度颜色优先。
- “播放 → 进度条外观 → 单独标出提前加载”只控制配色：关闭时，原生缓冲和插件缓冲均显示为亮灰色，覆盖范围不变，提前加载继续运行。插件范围由驻留分段的 SIDX 时间索引确定，并取当前音视频均就绪的交集；它与播放器 video.buffered 是不同来源的数据，但完整请求命中时可直接复用。
- 同一标签页的插件弹窗关闭后，再次打开会直接恢复上次的视频信息、画质和选择；快照过期时也会先显示旧状态、再在后台更新。
- 点击居中的“缓存”按钮缓存当前视频或当前分 P。不同画质使用独立缓存键，已有低画质不会阻止继续缓存更高画质。
- 下载前会用小范围请求比较主 CDN 与备用 CDN，然后以视频最多 4 路、音频独立 1 路的 2 MiB 固定范围并发缓存（单段 MP4 最多 4 路）；视频 + 音频任务会在两条轨道都完整后自动重封装为一个双轨 MP4，期间按钮显示“正在合并”；除失败/超时回退外，还会分开测量 TTFB 与正文吞吐，成功但持续慢首字节的节点也会在后续分块中被主动降级。
- 缓存任务开始后可以关闭弹窗、切换标签页，或关闭原视频页；下载由扩展的 Offscreen Document 继续执行。遇到签名地址过期、HTTP 403、限流或临时断网时，后台会刷新播放地址并从最后一个已落盘分块续传；原页不可用时会使用当前 Chrome 登录会话直接请求播放清单。可恢复错误按 1 分钟、2 分钟、之后每 5 分钟持续重试，不再在第 8 次后放弃；存储或媒体不兼容错误仍会停止并提示。浏览器退出、电脑休眠期间不能下载，重新运行后再恢复。Service Worker 重启或隐藏下载文档被回收后，分钟级看门狗会重新接管等待中的任务。
- 点击当前视频或片库中的 UP 主名称会打开其 B 站主页；在下方列表点击标题会打开原视频，完成项目的下载箭头会保存文件，垃圾桶按钮会删除缓存。
- 保存时，视频 + 音频缓存导出为一个包含两条轨道的 `.mp4`；仅音频缓存导出为一个音频文件，扩展名沿用 B 站原始格式（`fLaC` → `.flac`，AAC / 杜比 → `.m4a`，MP3 → `.mp3`）；只返回单段 MP4 的视频保存为 `.mp4`。如果某个缓存的重封装失败，保存按钮会退回分别导出 `.视频轨.mp4` 与 `.音频轨.m4a`，并给出“未能合并”的提示，而不是假装成功。
- 再次打开已经缓存的视频时，插件会自动切换到本地 MP4（合并后的单文件优先）；控制台会记录“已切换为本地缓存播放”。仅音频缓存不会顶替网页播放器，请从片库保存后在本地播放。
- 扩展只为自身发往 B 站视频 CDN 的下载请求补充 B 站 `Referer`，以满足 CDN 防盗链校验；不会修改其他网站的请求。
- 只有实际写入字节数与 CDN 报告的完整文件大小一致时，视频才会标记为“已缓存完成”。
- 播放地址优先由当前 B 站页面发起，以便使用该页面的真实登录会话；失败时才回退到扩展后台请求。扩展只读取 `SESSDATA` 是否存在来显示登录状态，不展示、复制或保存 Cookie 原始值；大会员内容能否访问仍以当前账号的实际权益和 B 站返回结果为准。

## 开发态热更新

安装依赖不是必需的。加载本目录中的未打包扩展后，在项目目录运行：

```bash
npm run dev
```

热更新服务会监听扩展的 JS、JSON、HTML、CSS 与图标文件。开发版由不会随 MV3 Service Worker 空闲休眠的 Offscreen Document 轮询仅绑定本机的修订端点；变化后约 1 秒内通知后台，把待刷新标记写入可跨扩展重载保留的 `chrome.storage.local`，再执行 `chrome.runtime.reload()`。新后台消费标记后只刷新已经打开的 B 站视频/列表页，使 `document_start` 的 MAIN/ISOLATED 脚本也自动更新。固定的 manifest 公钥保证扩展 ID 稳定；原位重载和页面刷新不会清除 IndexedDB，已经缓存的视频会保留，未完成下载会从最后一个已持久化分块自动续传。开发时正在播放的 B 站页面会被刷新，这是取得真正内容脚本热更新所必需的行为。

如果 Chrome 当前加载的是修复前的旧热更新器，需要在 `chrome://extensions` 对本扩展手动点一次“重新加载”，让新版 Offscreen 监听器接管；这是升级热更新器本身的一次性引导，之后修改工作区文件会自动重载扩展和 B 站页面，不需要每次再点。

不要删除 manifest 中的 `key`，也不要手动清除扩展存储；这两项分别关系到扩展身份和缓存数据连续性。

发布构建使用：

```bash
npm run build
```

命令会生成 `dist/unpacked` 与 `dist/bili-buffer-extension-<version>.zip`，并自动移除开发态热更新入口及 `127.0.0.1` 权限；开发目录本身仍保留热更新能力。

## 当前边界

- 支持标准 BV / av 投稿、分 P 和带 `bvid` 的稍后再看页面。番剧、互动视频、课程和特殊分段格式会显示不支持，不写入伪缓存。
- 画质选项只显示播放接口实际返回媒体轨道的档位，并按清晰度降序排列；不会把接口仅声明、但没有返回轨道的画质列为可缓存。
- 支持单段 progressive MP4，以及 Chrome MediaSource 能播放的 DASH 视频/音频 MP4 轨；不支持的编码、番剧和特殊多段格式会明确提示。
- 登录 Cookie 只能尝试恢复当前账号本来就有的观看和画质权限，不能绕过大会员、付费、地区或内容授权限制。
- 音视频合并由插件自己的 `src/mp4-merge.js` 在浏览器内完成重封装（不转码）：只支持 B 站使用的 fragmented MP4（`moov` 内含 `mvex`）；无法识别的布局会保留两条独立轨道并明确提示，不会写出看似完成但实际无声或损坏的文件。旧版本留下的双轨缓存会在播放或保存时自动合并升级，不需要重新下载。
- 合并需要完整读写一遍媒体数据，长视频在这一阶段会有一次额外的磁盘读写；合并成功后只保留一个单文件，不会长期占用双份空间。
- 视频体积和音频体积互相独立：同一个视频里，无损音轨（FLAC 约 1.4–1.8 Mbps）常常比低码率画面（例如静态封面的音乐 / 专辑视频）大好几倍。音乐合集类视频缓存出 400 MB 视频 + 1 GB 无损音频属于正常现象，不代表画质没取到最高档——画质看的是分辨率 / 帧率 / 编码档位，不是文件字节数。可用上面的“声明 vs 返回”对照确认是否已是最高的可用档位。
- B 站 Hi-Res 无损的原始文件是“MP4 容器 + FLAC 编码”（CDN 上的 `_30251.m4s`，`audio/mp4; codecs="fLaC"`）。插件按编码把它保存为 `.flac`，字节与 CDN 完全一致、不做任何转码；播放器把容器显示成 MP4 属于正常现象，音频本身是 FLAC 无损。片库保存按钮的悬停提示会写出实际的“容器 · 编码”。
- 只返回单段 MP4 的视频在“仅音频”下需要先下载整段 MP4 再提取音轨（B 站不提供该文件的音频分段，yt-dlp 也只能如此），因此这一次下载的流量等于整段视频；提取后只保留音频样本，缓存体积与保存文件都接近纯音频大小。
- 缓存仅保存在当前 Chrome 配置中；卸载扩展会删除缓存。
- Popup 界面快照使用 `chrome.storage.session`；浏览器重启、扩展禁用/重载，或首次打开某个视频时，仍需重新读取当前真实画质。
- 并发下载能绕开某些 CDN 的单连接限速，但不会突破当前网络总带宽；实际提速取决于视频节点、时段和跨境路由。
- 播放提前加载会产生额外流量，因为插件读完后播放器仍可能再次读取同一范围。开启后不再等待高延迟、播放时长、播放余量或标签页可见性；约 45 秒前方窗口、128 MiB 驻留上限、并发限制和节点错误退避仍用于约束流量与故障。关闭视频标签页会终止这条依附页面的提前加载；需要关页后继续时应使用“缓存”创建完整下载任务。
- 没有可解析 SIDX 的格式（包括普通 progressive MP4）、层级索引或只有单轨就绪时，不再用字节比例伪造黄色。签名 URL、CDN 或清晰度变化保守地视为不同资源；切分 P/视频会清理，容量回收后不再显示失去驻留数据的黄色。命中能省去下载，但关键帧定位、音视频同步与解码仍需时间，不能承诺任意拖动零等待。
- 播放器网络能力估计保护不使用固定“万能带宽”：只有同一 CDN 已积累至少 3 个正常请求样本且刚发生高延迟响应时，才按本机当前链路的保守分位数过滤关联低样本。关闭播放提前加载也会停用这项修正；Popup 不再展示诊断指标或手动重置入口。
- 只应用于用户有权观看的内容，并应遵守平台条款与版权要求。
