# Bili 缓冲站

面向海外网络环境的 Chrome Manifest V3 插件。它同时提供两条互补路线：播放提前加载开启时，观测播放器的首个 CDN Range 响应并立即请求后续字节，促使边缘节点提前回源；需要离线观看时，则通过当前 B 站页面的登录会话读取实际可用画质并完整缓存。默认选择账号可用的最高画质与同画质下码率更低的可播放编码；再次打开相同视频与分 P 时，可在原网页播放器中使用本地 Blob 或 MediaSource，保留控制条、倍速、进度与弹幕同步。

## 安装

1. 打开 `chrome://extensions/`。
2. 开启右上角“开发者模式”。
3. 选择“加载已解压的扩展程序”，选择本项目文件夹。
4. 打开标准 B 站视频页（`https://www.bilibili.com/video/BV...`）或带 `bvid` 的稍后再看页面，点击工具栏中的插件图标。

## 使用

- 面板按任务分为“缓存”“播放”“片库”三个页签，同一时间只展示一类内容；画质选择留在缓存页，播放提前加载开关和高亮颜色留在播放页，已缓存项目集中在独立片库页。可用鼠标点击，也可在页签上用左右方向键切换。
- 在“缓存画质”中选择清晰度；首次打开默认选中 B 站返回的最高可用画质。
- 缓存页显示当前画质的音视频总大小，切换画质时同步更新。下载前按码率和时长估算并标注“约”，取得完整大小后显示实际值。
- 缓存页不再展示编码选择；新任务自动选择同画质下 Chrome 可播放且码率最低的编码，减少需要下载的数据。
- “播放”页只保留“开启 / 关闭”。默认开启；页面一取得播放器首个媒体 Range 的响应头，插件就从该范围末尾开始提前请求后续字节，不再等待播放 20 秒、出现高延迟、播放器先积累 10 秒余量或标签页保持在前台。单轨仍最多额外读取 200 MB，并保留并发上限、超时、退避和失败停用保护。关闭后不再发起额外的 CDN 请求。
- B 站进度条中的纯色色段表示当前 DASH 视频轨和音频轨都已由插件请求过的 CDN 字节范围；单文件 MP4 则表示该媒体轨已请求。默认使用与原生粉/灰进度对比明显的橙色，播放辅助面板提供橙、黄、青、蓝、紫、粉六种预设和系统调色器的自定义颜色，选择会自动保存。原生亮灰色仍表示播放器真正保存在内存中的缓冲，深灰色表示尚未覆盖；色段没有顶部高光、阴影或渐变，也不会拦截点击和拖动。
- 未悬停或聚焦进度条时，如果当前已播放边缘进入插件提前加载色段，会出现一条跟随播放位置连续移动的白色竖线，区分“已经播放”和“尚未播放但已提前请求”。鼠标移入或键盘聚焦进度条时白线自动隐藏，避免干扰拖动、预览和定位。色段与白线表示对应 CDN 曾完整返回这些字节，不是“这一秒一定不会卡”的保证：播放器仍要重新取数据，且会受可变码率映射、节点切换、边缘淘汰或网络中断影响。开启后也要等视频、音频两条 DASH 轨各有成功范围并产生交集才会着色；点击“缓存”写入本地片库不会染色这条时间轴。
- 同一标签页的插件弹窗关闭后，再次打开会直接恢复上次的视频信息、画质和选择；快照过期时也会先显示旧状态、再在后台更新。
- 点击居中的“缓存”按钮缓存当前视频或当前分 P。不同画质使用独立缓存键，已有低画质不会阻止继续缓存更高画质。
- 下载前会用小范围请求比较主 CDN 与备用 CDN，然后以视频最多 4 路、音频独立 1 路的 2 MiB 固定范围并发缓存（单段 MP4 最多 4 路）；除失败/超时回退外，还会分开测量 TTFB 与正文吞吐，成功但持续慢首字节的节点也会在后续分块中被主动降级。
- 缓存任务开始后可以关闭弹窗、切换标签页，或关闭原视频页；下载由扩展的 Offscreen Document 继续执行。遇到签名地址过期、HTTP 403、限流或临时断网时，后台会刷新播放地址并从最后一个已落盘分块续传；原页不可用时会使用当前 Chrome 登录会话直接请求播放清单。可恢复错误按 1 分钟、2 分钟、之后每 5 分钟持续重试，不再在第 8 次后放弃；存储或媒体不兼容错误仍会停止并提示。浏览器退出、电脑休眠期间不能下载，重新运行后再恢复。Service Worker 重启或隐藏下载文档被回收后，分钟级看门狗会重新接管等待中的任务。
- 点击当前视频或片库中的 UP 主名称会打开其 B 站主页；在下方列表点击标题会打开原视频，完成项目的下载箭头会保存文件，垃圾桶按钮会删除缓存。
- 单文件缓存保存为一个 MP4；高画质 DASH 是 B 站返回的独立视频轨和音频轨，当前会分别保存为 `.视频轨.mp4` 与 `.音频轨.m4a`，避免生成看似成功但实际无声的文件。
- 再次打开已经缓存的视频时，插件会自动切换到本地 MP4；控制台会记录“已切换为本地缓存播放”。
- 扩展只为自身发往 B 站视频 CDN 的下载请求补充 B 站 `Referer`，以满足 CDN 防盗链校验；不会修改其他网站的请求。
- 只有实际写入字节数与 CDN 报告的完整文件大小一致时，视频才会标记为“已缓存完成”。
- 播放地址优先由当前 B 站页面发起，以便使用该页面的真实登录会话；失败时才回退到扩展后台请求。扩展只读取 `SESSDATA` 是否存在来显示登录状态，不展示、复制或保存 Cookie 原始值；大会员内容能否访问仍以当前账号的实际权益和 B 站返回结果为准。

## 开发态热更新

安装依赖不是必需的。加载本目录中的未打包扩展后，在项目目录运行：

```bash
npm run dev
```

热更新服务会监听扩展的 JS、JSON、HTML、CSS 与图标文件。开发版由不会随 MV3 Service Worker 空闲休眠的 Offscreen Document 轮询仅绑定本机的修订端点；变化后约 1 秒内通知后台，把待刷新标记写入可跨扩展重载保留的 `chrome.storage.local`，再执行 `chrome.runtime.reload()`。新后台消费标记后只刷新已经打开的 B 站视频/列表页，使 `document_start` 的 MAIN/ISOLATED 脚本也自动更新。固定的 manifest 公钥保证扩展 ID 稳定；原位重载和页面刷新不会清除 IndexedDB，已经缓存的视频会保留，未完成下载会从最后一个已持久化分块自动续传。开发时正在播放的 B 站页面会被刷新，这是取得真正内容脚本热更新所必需的行为。

如果 Chrome 当前加载的是修复前的旧热更新器，需要在 `chrome://extensions` 对本扩展手动点一次“重新加载”，让新版 Offscreen 监听器接管；这是升级热更新器本身的一次性引导，之后修改工作区文件会自动重载扩展和 B 站页面，不需要每次再点。

不要删除 manifest 中的 `key`，也不要手动清除扩展存储；这两项分别关系到扩展身份和缓存数据连续性。

发布构建使用：

```bash
npm run build
```

命令会生成 `dist/unpacked` 与 `dist/bili-buffer-extension-<version>.zip`，并自动移除开发态热更新入口及 `127.0.0.1` 权限；开发目录本身仍保留热更新能力。

## 当前边界

- 支持标准 BV / av 投稿、分 P 和带 `bvid` 的稍后再看页面。番剧、互动视频、课程和特殊分段格式会显示不支持，不写入伪缓存。
- 画质选项只显示播放接口实际返回媒体轨道的档位，并按清晰度降序排列；不会把接口仅声明、但没有返回轨道的画质列为可缓存。
- 支持单段 progressive MP4，以及 Chrome MediaSource 能播放的 DASH 视频/音频 MP4 轨；不支持的编码、番剧和特殊多段格式会明确提示。
- 登录 Cookie 只能尝试恢复当前账号本来就有的观看和画质权限，不能绕过大会员、付费、地区或内容授权限制。
- Chrome 不提供把两个 DASH Blob 自动合并成单个 MP4 的扩展 API；当前保存按钮对 DASH 采用双轨导出，本地缓存播放仍会把两轨同步播放。
- 缓存仅保存在当前 Chrome 配置中；卸载扩展会删除缓存。
- Popup 界面快照使用 `chrome.storage.session`；浏览器重启、扩展禁用/重载，或首次打开某个视频时，仍需重新读取当前真实画质。
- 并发下载能绕开某些 CDN 的单连接限速，但不会突破当前网络总带宽；实际提速取决于视频节点、时段和跨境路由。
- 播放提前加载会产生额外流量，因为插件读完后播放器仍可能再次读取同一范围。开启后不再等待高延迟、播放时长、播放余量或标签页可见性；单轨 200 MB 上限、约 45 秒前方窗口、并发限制和错误退避仍用于约束流量与故障。关闭视频标签页会终止这条依附页面的提前加载；需要关页后继续时应使用“缓存”创建完整下载任务。
- 预热高亮按“字节偏移 ÷ 轨道总大小”映射到时间轴，因此是位置近似值；DASH 只显示当前视频轨与音频轨预热范围的交集，避免单轨成功被误报成整段就绪，但可变码率、CDN 节点切换/淘汰、签名失效和后续网络变化仍可能使高亮区间发生卡顿。它不代表该段已经存进浏览器本地缓冲。
- 播放器网络能力估计保护不使用固定“万能带宽”：只有同一 CDN 已积累至少 3 个正常请求样本且刚发生高延迟响应时，才按本机当前链路的保守分位数过滤关联低样本。关闭播放提前加载也会停用这项修正；Popup 不再展示诊断指标或手动重置入口。
- 只应用于用户有权观看的内容，并应遵守平台条款与版权要求。
