海内存知 · 隐私说明

最后更新：2026-10-26 · 适用于扩展版本 2.6.3 及以后

本扩展没有用于接收用户缓存或账号信息的服务器，所有缓存、偏好与任务状态都保存在你自己的 Chrome 配置里。GitHub 版按你的操作访问发布服务获取更新，详见下文。

1. 扩展会接触哪些数据

数据用途存放位置与保留时间
登录态是否存在（SESSDATA） 只判断“当前是否已登录”，用于在面板上显示登录提示。只读取该 cookie 是否存在，不读取、不保存、不传输它的值。 不落盘。每次需要时重新查询一次。
当前标签页地址 识别 BV 号与分 P，构造该视频的播放清单请求，并在片库中判断“这个视频是否已缓存”。 chrome.storage.session 里的界面快照，浏览器重启或扩展重新加载即失效。
你主动缓存的视频 / 音频数据 按你的操作从 B 站 CDN 下载并保存在本机，供离线播放与导出。 本机 IndexedDB。你在片库中删除，或卸载扩展时清除。
偏好设置（缓存内容、画质、进度条配色、提前加载开关） 下次打开面板时恢复你的选择。 chrome.storage.local。删除扩展数据或卸载扩展时清除。
缓存任务进度与失败原因 显示进度、速度与重试状态，并在扩展重启后续传。 chrome.storage.local 与本机 IndexedDB。

2. 扩展不会做的事

  • 不收集、不上传浏览历史，不记录你访问过的其他网站。
  • 不读取 cookie 的值，不读取表单内容、密码或剪贴板。
  • 不包含分析、埋点、遥测或广告 SDK，不注入广告，不替换网页内容。
  • 不把数据卖给或转让给第三方，不用于个性化广告，不用于信用评估或借贷判断。
  • 不把数据用于与“缓存 B 站视频”无关的任何目的。

3. 数据流向

缓存和播放功能与以下 B 站域名通信：*.bilibili.com、*.bilivideo.com、 *.bilivideo.cn、*.hdslb.com、*.akamaized.net。 这些请求由你点击“缓存”或开启“提前加载”后发起，内容与你直接播放视频时浏览器发出的请求相同。 扩展为这些 CDN 请求补上 B 站 Referer 以满足防盗链校验，不会修改其他网站的任何请求。 GitHub 解压版还会按需连接下文披露的 GitHub 更新域名；扩展不连接开发者运营的服务端。

4. 数据删除

  • 在片库中点击垃圾桶按钮：删除该视频的缓存与任务记录。
  • 在 chrome://extensions 中清除扩展数据或卸载扩展：删除全部本地数据。
  • 因为不存在服务器，开发者侧没有任何副本可供删除或导出。

5. 权限用途

权限用途
activeTab读取当前标签页的地址，判断它是不是支持的 B 站视频页；否则只能显示“无法读取当前页面”。
alarms分钟级看门狗，在 Service Worker 被回收后重新接管等待中的缓存任务。

9. 官网的「扔一只漂流瓶」计数

这一节只涉及官网 haineicunzhi.kihara.cn，与扩展无关：扩展本身仍然不连接任何开发者服务器。

  • 官网首页有一个匿名点赞计数。滚动到这一节附近时，页面会向开发者自己的服务器 kihara.cn 请求当前计数；点击「扔一只瓶子」时再发送一次，内容只有一个可选的预设标签（如「离线缓存好用」），没有自由文字。
  • 请求不携带 Cookie，服务器不记录访问日志。为防止刷票，同一 IP 每天只计一次：服务器只保存「IP + 当天日期」经带密钥哈希后的摘要，两天后连摘要一起删除，不保存原始 IP。
  • 你的浏览器会在本机 localStorage 里记下扔瓶子的日期，只用于刷新后不再显示按钮；清除网站数据即可删除。
  • 计数服务的源码在仓库的 server/bottles/ 目录，可以自行核对。

Privacy Policy (English)

This extension has no server for receiving cached media or account information. All cached media, preferences and task state stay in your local Chrome profile. The GitHub edition contacts release services for updates when you request it, as disclosed below.

  • Login state: it only checks whether the SESSDATA cookie exists in order to show a login hint. The cookie value is never read, stored or transmitted.
  • Current tab URL: used to identify the video you are watching and to look up its cached copy. Kept in chrome.storage.session only.
  • Cached media: downloaded from Bilibili CDNs only when you click "cache", and stored in your local IndexedDB.
  • Preferences and task progress: stored in chrome.storage.local so progress can resume after a restart.
  • No analytics, telemetry, ads, or third-party SDKs. No selling or transferring of data. No browsing-history collection.
  • For caching, network access is limited to *.bilibili.com, *.bilivideo.com, *.bilivideo.cn, *.hdslb.com and *.akamaized.net.
  • Deleting a video from the library, clearing the extension's data, or uninstalling the extension removes all local data.
  • Website only: the "Throw a bottle" counter on haineicunzhi.kihara.cn fetches an anonymous count from the developer's own server (kihara.cn) and, when you click the button, sends one optional preset tag and no free text. No cookies are sent and no access logs are kept. To limit repeat votes, the server stores only a keyed hash of "IP + date", deleted after two days; raw IPs are never stored. The page remembers the date you threw a bottle in localStorage. The extension itself never contacts this server.

The use of information received from Google APIs will adhere to the Chrome Web Store User Data Policy, including the Limited Use requirements.

GitHub edition updates: after an explicit update check and optional permission grant, the unpacked edition contacts api.github.com, github.com, release-assets.githubusercontent.com and objects.githubusercontent.com for release metadata and signed packages. Requests omit Bilibili cookies and never upload cached media, account data or folder contents. GitHub receives normal request metadata. The store edition only links to downloads and updates through Chrome Web Store.

The selected installation folder handle and recovery snapshots stay in a separate local IndexedDB. Chrome may request write access again; it can be revoked through page permissions. Snapshots are removed after verified success or completed recovery. Folder access is used only to update extension files.

本页面可离线打开；扩展包内的 privacy.html 与线上版本内容一致。
